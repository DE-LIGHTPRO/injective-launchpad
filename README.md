# inj·pad

A one-sided bonding curve launchpad on Injective. The creator supplies **only
tokens**; buyers bring INJ, and the curve prices every trade until it graduates
and the liquidity migrates.

Currently a **demo**: the launches on the page are generated locally from the
real curve maths, no contracts are deployed, and the banner says so on every
page. That banner is load-bearing — see "Demo mode" below.

## Layout

```
packages/launchpad-math/   The curve. Pure Rust, no chain access.
contracts/curve/           One launch: buy, sell, graduate, claim fees.
contracts/factory/         Creates curves, keeps the registry.
app/                       Next.js front end.
scripts/deploy.mjs         Deploys the factory and stores the curve code id.
```

## Tests

```bash
cargo test            # 42: the maths, both contracts
npm --prefix app test # 20: the TypeScript port, parity, env surface
```

### The curve exists twice, and that is the main hazard

`app/src/lib/curve.ts` is a hand-written mirror of `packages/launchpad-math` so
the UI can quote a trade without a round trip. If the two disagree by **one
unit**, the quote shown is wrong and trades near the graduation boundary revert
on slippage.

So the parity vectors are generated by the Rust, not written by hand:

```bash
npm --prefix app run vectors   # writes app/src/lib/curve-vectors.json
```

The TypeScript test reads that file, asserts the config in it matches its own
before trusting a single number, and re-runs the generator to fail if the
committed file has gone stale. Where `cargo` is absent that last check skips
loudly rather than passing, because a drift check reporting green on a machine
it could not run answers a question it never asked.

A third consumer is the contract's own `SimulateBuy` / `SimulateSell`, which the
UI quotes from. `contracts/curve` asserts those equal what executing actually
does. One implementation of the maths, three consumers, all of which must agree.

## Configuration

Two surfaces, deliberately separate:

- `app/.env.example` — everything the browser reads. All `NEXT_PUBLIC_*`, which
  Next.js **inlines into the client bundle** at build time exactly like Vite's
  `VITE_*`, so none of them may ever hold a secret.
- `scripts/.env.example` — what the deploy script reads, including the signing
  credential. Unprefixed, so it cannot reach the bundle.

`src/lib/env-surface.test.ts` asserts both files document exactly what the code
reads, in both directions, and that no secret-shaped variable carries the public
prefix. A variable nothing reads advertises a switch that does nothing; one the
code reads and nobody wrote down is a step missing on deployment day.

## Demo mode

`NEXT_PUBLIC_DEMO` is set while no factory is deployed. Remove it only once
`NEXT_PUBLIC_FACTORY_ADDRESS` points at a real one. Removing it first leaves the
page showing prices that nothing backs, with no banner saying so — the curve
maths are real, but a price computed from a launch that does not exist is not a
market price.

Testnet is the default everywhere. Mainnet is never a fallback.
